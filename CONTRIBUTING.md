# Contributing to SnapData

## Development Principles

- Follow the approved SnapData repository architecture.
- Keep presentation, application, domain, processing, persistence, export, model-management, platform, and core responsibilities separated.
- Prefer small, focused changes.
- Do not introduce unapproved mandatory backend, REST, or cloud dependencies into the MVP.
- Do not commit secrets, private documents, credentials, signing keys, or generated release artifacts.
- Add or update tests for behavioral changes.
- Mark unconfirmed technology decisions as `REQUIRES TECHNICAL VALIDATION`.

## Pull Requests

Pull requests should explain the change, validation performed, and any remaining technical risks. Avoid unrelated refactoring.
